# 设备故障快速记录系统 V1.1（修订 1.1.1）

正式网址：https://check.saka77.cn/

React + TypeScript + Vite。仅更新本仓库，由原 GitHub Actions 测试、构建并发布 GitHub Pages。域名和 DNS 保持不变。

> 本修订按《完整开发需求与技术规范》§4.4 / §4.5 修正了花园连续记录逻辑。旧版记录一条后自动返回塔选择，与规范冲突，已改。

## 快速记录

**花园（§3–§4）**
花园 → T1–T9 → 1–8 号；编号自动生成 `7 + 塔号 + 两位灯号`（如 T6/8号 = 7608），共 72 个。
默认记录“不亮”，无需先点不亮。塔内勾选“不受控”后点灯号记录为不受控，**记录后故障类型自动恢复为不亮，塔号保持选中**，可连续点击同一塔的多个灯号（如 T6 依次点 1、3、8），也可通过灯具上方的塔号条直接切换到其他塔，无需返回。花园允许重复编号，每条记录有独立 ID。

**外围灯（§5–§7）**
7 个区域、27 个灯具，顺序与映射严格按规范 §6.1–§6.7（219A/Roof1、219B/Roof7、小飞象·提摩太小吃/Roof2、小镇/Roof3、33屋顶/Roof4、医务室/Roof5、12朋友园/Roof6，覆盖 7001–7027 不重不漏）。
绿色 = 当天未标记（不是“已确认正常”），点击变红并新增 `RoofX，编号` 记录，再点红色变绿并删除当天对应记录。同一灯具同一天最多一条有效记录。红绿状态始终由当天已保存记录派生：刷新后保持、从主列表删除后变绿、清空当天后全部变绿。

**城堡**
底部保留城堡入口。本次规范未提供城堡设备数量与编号规则，页面为待配置提示，未擅自编造编号。

## 记录管理（§2）
- 顶部：系统名、北京时间（Asia/Shanghai）日期、今日故障数实时计算。
- 主列表最新在上，编号大字显示；花园显示故障类型，外围灯显示 Roof + 编号，每条保留记录时间。
- 单条删除、撤销上一项操作（本次会话内可撤销新增/删除/外围灯切换/清空，基于操作前快照恢复）、复制所选日期全部记录、清空所选日期（二次确认）、历史日期查看、导出全部历史 CSV。
- 数据自动保存到 localStorage，刷新不丢失；存储键 `equipment-check-v1` 保持不变，旧记录原样读取、不补写故障类型。

## 数据安全
记录仅保存在当前设备、浏览器和域名，不跨设备同步。请定期导出 CSV。不要清除网站数据。PWA 升级仅删除本工具旧 Cache Storage，保留 localStorage；可点击新版本提示刷新。Safari 分享 → 添加到主屏幕。

## 开发与部署
Node 22+；`npm ci`；`npm test`；`npm run build`；`npm run dev`。

推送到 `main` 后，`.github/workflows/pages.yml` 自动跑测试、构建并发布 GitHub Pages（自定义域名 check.saka77.cn）。
